# 요구사항

## 문제 정의

SAP PO와 RTIMS 운영 정보가 여러 화면·서버·데이터 원본에 분산되어 있어 장애 인지, 메시지 추적, 채널 운영, HRD 일일 점검에 반복 작업과 판단 지연이 발생한다.

## 대표 시나리오

1. 운영자가 권한이 있는 서버 전체의 메시지량·성공률·지연·Queue를 확인한다.
2. 채널을 검색해 메시지 목록을 보고 Message ID의 CC/Audit 로그를 추적한다.
3. 시스템별 채널 상태를 확인하고 권한이 있으면 단건 또는 대량 제어한다.
4. 법인코드·테이블을 체크박스로 선택해 HRD 인터페이스를 조회·다운로드·테스트한다.
5. 알림에서 오류 문맥을 확인하고 내부 LLM JSON 분석을 요청한다.

## 기능 요구사항

| ID | 요구사항 | 우선순위 | 수용 기준 | 상태 |
|---|---|---|---|---|
| FR-001 | 로그인과 역할별 메뉴·서버 접근 | Must | ADMIN·OPERATOR·VIEWER 권한을 backend가 검사 | 구현 |
| FR-002 | `.env` 서버 추가 자동 반영 | Must | backend 재시작 후 코드 변경 없이 서버 목록 노출 | 구현 |
| FR-003 | 독립 로딩 대시보드와 15분 갱신 | Must | 기존 값을 유지하며 widget별 완료 시 데이터만 교체 | 구현 |
| FR-004 | 24시간 트래픽과 1시간·1일 집계 | Must | 전체·서버별 필터와 메시지량·크기 tooltip 제공 | 구현 |
| FR-005 | 채널 검색 기반 메시지·Audit 추적 | Must | 채널→메시지 목록→Message ID→CC 로그 흐름 | 구현 |
| FR-006 | 시스템별 채널 정보와 상세 | Must | 시스템 선택 후 채널 목록·상세 확인 | 구현 |
| FR-007 | 단건·대량 채널 제어 | Must | 권한·preview·진행 상태·실패 결과 제공 | 구현, 사내 검증 필요 |
| FR-008 | HRD 선택 조회·Excel·테스트 메시지 | Must | 법인코드·테이블 전체 선택과 개별 선택 지원 | 구현, 사내 검증 필요 |
| FR-009 | RTIMS 리소스·Queue·장애·실시간 내역 | Must | 원본 단위와 상태 코드를 유지해 조회 | 구현, 사내 검증 필요 |
| FR-010 | Oracle IFS 동기화 | Must | 수동 실행·마지막 결과·cache 상태 확인 | 구현, 사내 검증 필요 |
| FR-011 | 사용자 대시보드·즐겨찾기·워크스페이스 | Should | 사용자별 설정과 소유권이 PostgreSQL에 유지 | 구현 |
| FR-012 | 알림과 LLM 분석 | Should | 마스킹된 JSON 요청·응답 계약과 실패 상태 제공 | 부분 |
| FR-013 | Collector 증분 수집 | Should | checkpoint·시간창·중복 제거·페이지 처리 | 부분 |

## 비기능 요구사항

| ID | 영역 | 요구사항 | 확인 방법 |
|---|---|---|---|
| NFR-001 | 성능 | 평균 응답 시간은 초 단위 `0.000초` 형식으로 표시 | UI와 formatter 테스트 |
| NFR-002 | 가용성 | 외부 API 지연이 전체 대시보드 로딩을 차단하지 않음 | timeout·fallback 테스트 |
| NFR-003 | 보안 | 비밀값과 내부 URL은 frontend·Git·문서에 노출하지 않음 | 코드 리뷰·추적 파일 검사 |
| NFR-004 | 권한 | 메뉴 숨김과 무관하게 backend가 permission과 서버 범위를 검사 | API 권한 테스트 |
| NFR-005 | 이식성 | Python 3.11.7, npm 11.13.0 기준 사내망 설치 가능 | 설치 가이드와 사내 smoke test |
| NFR-006 | 유지보수 | 코드 변경과 도메인 5개 문서·테스트가 같은 책임 경계를 유지 | 문서 validator와 리뷰 |
| NFR-007 | DB | PostgreSQL 식별자 소문자 snake_case와 순번 migration 유지 | migration 리뷰 |

## 범위와 미결정 사항

현재 구현·부분 구현·사내 검증 대상의 상세 기준은 [`LEGACY_FEATURE_COVERAGE.md`](LEGACY_FEATURE_COVERAGE.md)를 사용한다. 실제 상태 코드·필드명·임계값은 사내 SAP PO·RTIMS 원본 확인 후 확정한다.
