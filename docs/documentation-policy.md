# 문서 정책

## 목적

문서를 많이 만드는 것이 아니라 AI와 사람이 필요한 근거만 빠르게 찾고, 코드와 계약의 불일치를 자동으로 발견하도록 한다.

## 안정 지식과 변동 상태

| 유형 | 문서 |
|---|---|
| 안정 지식 | `PROJECT.md`, 영역·도메인 `README.md`, `MANUAL.md`, `SKILL.md`, `API.md`, ADR |
| 오류 지식 | 루트·영역·도메인 `ERROR.md` |
| 변동 상태 | `CURRENT_TASK.md`, `ROADMAP.md`, `CHANGELOG.md` |

## 도메인 문서 계약

- `README.md`: 책임, 제외 범위, 코드 위치, 선행·후행 도메인
- `MANUAL.md`: 설치, 실행, 테스트, 디버깅, 기능 추가 절차
- `SKILL.md`: AI가 읽고 구현·검증하는 순서와 금지사항
- `ERROR.md`: 증상, 재현, 원인, 해결, 검증, 재발 방지
- `API.md`: method, route, permission, request/response, 외부 원본, frontend consumer

템플릿의 `DOMAIN.md`, `ERRORS.md`, `SKILLS.md`를 별도로 복제하지 않는다. 현재 파일이 동일 역할의 단일 기준이다.

## 최소 문맥

- 기본적으로 `AGENTS.md`, `PROJECT.md`, `CURRENT_TASK.md`만 읽고 작업 유형에 따라 필요한 문서로 이동한다.
- 관련 없는 도메인 전체, 대형 로그, 배포 문서는 읽지 않는다.
- 먼저 파일명·키워드·심볼·테스트를 검색하고 관련 구간만 연다.
- API나 여러 도메인의 공개 계약이 바뀔 때만 영향 도메인 문서를 추가로 읽는다.

## 갱신 기준

반드시 갱신:

- 기능 동작·API·권한·외부 원본 변경
- 도메인 책임 또는 관계 변경
- 설정·빌드·배포·테스트 방법 변경
- 모든 해결된 오류와 검증 실패
- 중요한 기술 결정과 사용자·운영 영향

내용 정리만 가능:

- 중복 설명 제거
- 낡은 설명 교체
- 링크·색인 갱신
- 완료된 임시 작업 정보 제거

## 수명주기

- 같은 내용을 새 문서에 복사하기 전에 기존 기준 문서를 수정할 수 있는지 확인한다.
- 오래된 설명은 남겨두지 말고 수정하거나 제거한다.
- `CURRENT_TASK.md`는 활성 작업이 없으면 `IDLE` 상태와 사용 지침만 남긴다.
- `ERROR.md`의 해결책이 더 이상 유효하지 않으면 폐기 사유를 기록하거나 정리한다.
- 문서가 길어지면 세부 문서로 분리하고 원본은 지도와 링크 중심으로 축소한다.
